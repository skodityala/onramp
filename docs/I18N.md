# Internationalisation

## How it works

`src/copy.ts` holds all user-facing strings. It exports:

- `COPY` - the English strings, as a `const` object.
- `COPY_ES`, `COPY_FR` - Partial translations for Spanish and French.
- `COPIES: Record<Locale, Record<key, string>>` - merged tables. Missing keys in `COPY_ES` or `COPY_FR` fall back to English via object-spread.
- `getCopy(locale)` - returns the merged table for a locale.
- `getExamples(locale)` - returns the example prompts for a locale.
- `detectLocale()` - reads the primary subtag of `navigator.language`. Anything unrecognised returns `en`.

Views consume the copy through a small React context (`LocaleContext`) provided by `App.tsx`. The context defaults to `en`; the user can switch via a language selector in the top-right toggle area.

## How to add a locale

1. Define a `COPY_XX: Partial<Record<keyof typeof COPY, string>>` in `src/copy.ts`. Only translate the keys you have wording for; the rest fall back to English.
2. Add the locale to the `Locale` union type.
3. Add an entry to `COPIES`: `xx: { ...COPY, ...COPY_XX }`.
4. Optionally add `EXAMPLES_XX` and register it in `EXAMPLES_BY_LOCALE`.
5. Update `detectLocale()` to recognise the new subtag.
6. Add a smoke test in `src/__tests__/i18n.test.tsx` asserting the tagline for the new locale.

## Fallback strategy

Any missing key in a non-English locale falls back to the English string. This is by design: a partial translation is more useful than none, and it never crashes the UI.

## What is NOT translated

- The atomicity checker's lexicon (`src/core/lexicon.ts`) is English-only. Word lists (verbs, decision markers, stop markers, physicalisation targets) match English patterns.
- The 30 templates in `src/core/templates.ts` match on English keywords and produce English step text.

To fully support a non-English locale, a contributor would need to translate the lexicon and templates too. That is on the roadmap.

## Why we do not force a locale

`detectLocale()` runs once at boot and sets an initial default. The user always sees a language selector and can override. We never lock the user into a locale based on IP or account settings, because neither exists.

## Copy discipline in non-English locales

The banned-word list (`src/core/__tests__/copy.test.ts`) checks English substrings only. Translators should preserve the tone: neutral, no praise, no gamification vocabulary. If a Spanish or French phrase would use a comparable praise-word, rewrite it neutrally. Examples of what to avoid:

- Spanish: "¡Muy bien!", "¡Genial!", "¡Perfecto!" - all praise, all rejected.
- French: "Bravo !", "Super !", "Formidable !" - all praise, all rejected.

The Spanish and French translations shipped in this repo have been reviewed for tone alignment. Additional locales should follow the same principle.
